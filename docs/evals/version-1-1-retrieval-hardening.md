# Agent V1.1 检索边界加固评测

## 目标与方法

本轮运行时间：`2026-09-20T14:33:09Z`。

目标是验证轻量词法检索能否把“资料中出现过某个实体”和“资料足以支持这个问题”区分开，同时不牺牲已有事实问题的来源召回。评测通过真实 FastAPI `/api/chat` 路径运行，模型适配器在进程内替换为 Fake Provider，不访问网络、不消耗模型额度。

Version 1.1 在原有 28 条案例上增加 12 条变体，共 40 条，覆盖个人事实、项目事实、同义改写、资料外问题和对抗表达。机器结果只保存聚合指标、案例 ID、来源、调用次数和耗时；本报告不记录完整问题、回答、请求头、密钥或供应商原始异常。

## 有效改动

第一层是窄范围的组合阻断：只有动作词和目标词同时出现时，才拦截编造资料、泄露内部提示或读取主机文件的请求。单独出现“系统”“文件”或“配置”不会触发阻断，正常架构问题仍可以进入检索。

第二层是有效事实证据门控。姓名、项目名和“系统”“项目”“工作”等低信息词仍可参与排序，但不能单独让片段进入 Top-K。候选必须命中至少一个有效事实词；同义词表只把英语、岗位、贡献、多目标追踪、容器等常见表达映射到语料中已有词，不生成新事实。

同时收紧了中文滑动 n-gram 的边缘语法噪声，并保留原有内容分数、标题分数、稳定顺序和 `top_k` 行为。

## 失败案例与人工复核

本次自动评测没有失败案例 ID。自动指标只能说明当前 40 条固定案例通过了 API、来源、字符串代理和短路断言；仍应人工抽查正常问题、资料外问题和变体表达，确认拒答措辞、上下文相关性和回答完整性。

## 局限

这是固定小语料上的规则检索精度结果，不等同于通用语义理解、模型回答质量或完整的 Prompt Injection 防御。别名覆盖是人工维护的有限集合，新增项目和博客后仍可能出现未覆盖的改写。Fake Provider 只验证请求边界和上下文流转，不验证真实模型的自然语言表现。

## 下一步决策

暂不因为这一轮结果引入向量数据库、Embedding、LangChain 或多 Agent。先继续扩充脱敏资料和评测案例，保持同一指标口径；当语料规模和同义改写足以暴露词法方案的召回瓶颈时，再用相同案例比较当前词法门控、BM25/混合检索和 Embedding 检索的边界精度、召回收益、成本与部署复杂度。
