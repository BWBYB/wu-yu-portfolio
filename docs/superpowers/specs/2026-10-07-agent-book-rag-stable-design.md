# Agent Book 前三章 RAG 稳定版设计

## 目标

将 Agent Book 前三章导入本地 Dify 知识库，形成一个可复现的 RAG 验证版本，并把验证过程整理为个人网站上的中文博客雏形。博客同时记录“学习资料问答平台”的最小可行方向，但不在本阶段开发新平台。

## 范围

- 导入固定仓库版本中的 `chapter3.md`。
- 沿用现有知识库配置：通用切分、最大分段长度 1024、重叠长度 50、连续空白清洗、高质量向量索引。
- 用每章两个问题进行最小召回验证，记录命中文档、Top-K 和最高分。
- 用一个跨章节问题验证前三章共享知识库的回答能力。
- 用一个资料外问题验证拒答边界。
- 新增一篇 `status: organizing` 的中文博客草稿。

## 非目标

- 不统计本阶段 token 成本；博客只保留后续补充成本数据的字段和说明。
- 不发布 Dify 应用，不上线个人网站，不修改 Vercel/OpenShip 配置。
- 不实现学习资料问答平台，不引入新的后端、数据库或页面组件。

## 验收标准

1. `chapter3.md` 在 Dify 知识库中显示为“可用”。
2. 前三章至少有 6 个召回问题的记录，记录包含问题、期望章节、命中文档、召回段数量和最高分。
3. Chatflow 能回答一个第三章问题，并能对个人项目等资料外问题明确拒答。
4. 博客草稿包含数据来源、切分参数、流程、验证结果、失败边界、成本占位和平台方向评估。
5. Astro 内容集合检查通过，博客保持 `organizing`，不改变网站导航或页面组件。

## 记录原则

- 召回相似度只能作为检索信号，不能直接等价为答案正确率。
- 事实性结论必须回到召回文本核对。
- 第三方方案只作为选型参考，不宣称已经部署或完成生产验证。
